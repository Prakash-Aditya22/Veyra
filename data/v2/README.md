# Blackspot scores v2: backend contract

> **Full reference (Phase 3): [`INTEGRATION_CONTRACT.md`](INTEGRATION_CONTRACT.md).** It covers
> every field's type, units and empty-value rule, score semantics, CRS, ID rules, versioning and
> the optional extensions. Validate with `ml/audit/validate_contract.py`. Order by `rank`: the CSV
> score is rounded to 6 significant digits.

**What changed for the backend:** nothing breaks. The v1 files in `data/` are
untouched. The v2 files here contain **every v1 column, with the same name, in
the same order, first**, followed by new columns. A v1 loader reading only v1
columns works unchanged. Segment IDs are new; see below.

| File | Rows | Use |
|---|---|---|
| `road_segments_ranked_v2.csv` | top 50,000 by score + every segment with ≥ 6 crashes in 2023–25 | load into PostGIS (same table shape as v1, plus columns) |
| `road_segments_top500_v2.json` | top 500 | serve directly while the DB is set up |
| `road_segments_top5000_v2.geojson` | top 5,000 with **real road-centreline geometry** (OS Open Roads) | draw on the map as lines |
| `road_segments_meta_v2.json` | — | version, model, frozen-spec hash, forecast period, column notes |

The full national table (1.83 M segments) is regenerated by
`.venv/Scripts/python ml/pipeline.py forecast` into
`ml/outputs/road_segments_v2_full.parquet`. It is not in git because of its size.

## What the score means

`blackspot_score` = **expected killed-or-seriously-injured casualties on this
segment in 2026–2027**, on DfT's severity-adjusted scale. It is a forecast made
from 2023–25 history by a model whose form was fixed on 2015–2023 data and
tested on 2024–25 outcomes it never saw (see `ml/reports/final_audit.md`).

It is a **burden**, not a risk rate. A busy road ranks high because many people
use it. Two other measures sit beside it, for different questions:
- `eb_excess_ksi_history`: KSI above what similar roads (same class, layout, junctions, network density) would expect, Empirical Bayes. "Where is the road itself worse than it should be?"
- `ksi_per_100m_vkm_eb`: KSI per 100 million vehicle-km, **only where `exposure_available`** (M/A roads with a matched DfT traffic count). Empty elsewhere. No proxy is substituted.

## Columns

v1 columns (same names, same order):

| Column | v2 meaning | Note |
|---|---|---|
| `rank` | 1 = highest `blackspot_score` among all 1.83 M scored segments nationally | ranks are national, so the file has gaps where low-crash segments were not exported |
| `segment_id` | e.g. `A23-1C8A3D707069-02` | **new IDs**, stable for a given OS Open Roads release; not comparable to v1 `A23_run3_km0.5` |
| `location` | `A23 (Brixton Road) 1.0-1.5 km of stretch 3` | |
| `road_id` | road number, or `C` / `U` / `N` for unnumbered roads | |
| `km_from`, `km_to` | distance along the junction-to-junction stretch | not a milepost |
| `lat`, `lon` | segment midpoint (WGS84) | use for the pin; use the GeoJSON for the line |
| `blackspot_score` | see above | **rank by this** |
| `n_crashes`, `n_ksi`, `n_fatal` | collisions, KSI collisions, fatal collisions in 2023–25 | same units as v1, new window |
| `ksi_rate` | `n_ksi / n_crashes` | |
| `crashes_per_year` | `n_crashes / 3` | |
| `speed_max`, `pct_night` | max speed limit; share of crashes 22:00–05:59 | |
| `pct_junction` | v1 definition (`junction_detail != 0`) | roundabouts count as "not junction" under DfT's 2024 coding; prefer `pct_junction_v2` |
| `future_ksi`, `future_fatal` | **empty** | the forecast period has not happened; holdout outcomes are in `ml/reports/` |

New columns: `run` (stretch ordinal, for drawing a road in order only),
`score_version`, `score_model`, `score_definition`, `forecast_period`,
`history_period`, `road_class`, `road_number`, `road_name`, `form_of_way`,
`length_m`, `os_first_link_id` (geometry reference into OS Open Roads), `piece`,
`pct_junction_v2`, `n_ksi_casualties`, `n_ksi_casualties_adjusted`,
`eb_expected_ksi`, `spf_expected_ksi_history`, `eb_ksi_history`,
`eb_excess_ksi_history`, `eb_weight`, `aadf`, `aadf_count_point`,
`aadf_share_counted`, `exposure_available`, `vehicle_km_history`,
`ksi_per_100m_vkm_eb`, `eb_excess_ksi_exposure`, `data_sufficiency`,

## UI rules

1. Show `blackspot_score` as "expected serious or fatal casualties, 2026–27", not as "risk" and not as "predicted severity".
2. Grey out or hide segments where `data_sufficiency != "sufficient"` (fewer than 6 crashes in 2023–25). Their scores lean on road-type averages.
3. Show the exposure rate only where `exposure_available` is true.
4. Do not present SHAP or police-force effects as causes.
5. Label segments with `single_event_flag` (one mass-casualty collision supplied most of the
   history, e.g. the May 2025 Liverpool parade incident on Water Street). They are not road-design
   blackspots. 104 segments nationally, 1 in the top 500.
6. For per-vehicle rates, ignore segments shorter than ~250 m (tiny traffic denominators).

## Suggested SQL

```sql
CREATE TABLE road_segment_v2 (
  segment_id TEXT PRIMARY KEY, rank INTEGER NOT NULL, location TEXT, road_id TEXT, run INTEGER,
  km_from DOUBLE PRECISION, km_to DOUBLE PRECISION, geom GEOGRAPHY(POINT,4326) NOT NULL,
  blackspot_score DOUBLE PRECISION NOT NULL, n_crashes INTEGER, n_ksi INTEGER, n_fatal INTEGER,
  ksi_rate DOUBLE PRECISION, speed_max DOUBLE PRECISION, pct_night DOUBLE PRECISION,
  road_class TEXT, length_m DOUBLE PRECISION, eb_excess_ksi_history DOUBLE PRECISION,
  ksi_per_100m_vkm_eb DOUBLE PRECISION, exposure_available BOOLEAN, data_sufficiency TEXT,
  score_version TEXT, forecast_period TEXT
);
CREATE INDEX ON road_segment_v2 USING GIST (geom);
CREATE INDEX ON road_segment_v2 (blackspot_score DESC);
CREATE INDEX ON road_segment_v2 (road_id, run, km_from);
```
